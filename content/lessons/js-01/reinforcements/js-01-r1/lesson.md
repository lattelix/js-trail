# Практика JS 01 — сохрани значение до перезаписи

Ответа на предыдущую задачу пока нет, поэтому не переходим к типам и не накапливаем задания. Эта практика заменяет вчерашнюю. Базовый режим — 25–35 минут.

Вспомни без конспекта: что даёт вычисление выражения? Что делает присваивание с прежним значением переменной?

**Главный концепт:** присваивание заменяет текущее значение переменной. Если прежнее значение понадобится позже, его нужно сохранить под другим именем **до** перезаписи.

Разобранный пример:

```js
"use strict";

let fuel = 40;
let fuelBeforeTrip = fuel;
fuel = fuel - 12;

console.log(fuelBeforeTrip, fuel); // 40 28
```

При инициализации `fuelBeforeTrip` читается текущее значение `fuel`: число `40`. Затем выражение `fuel - 12` вычисляется, и результат `28` присваивается `fuel`. Между именами не возникает автоматически обновляемой связи.

Это учебное описание поведения JavaScript, а не утверждение о внутреннем устройстве памяти V8. Здесь используются числа: мутации объектов нет.

**Обязательная задача — восстанови старое значение.** Среда: Node.js, обычный файл `practice.js`, строгий режим. Автор хотел вывести запас товара до и после продажи:

```js
"use strict";

let stock = 10;
let sold = 4;

stock = stock - sold;
let stockBeforeSale = stock;

console.log(stockBeforeSale, stock);
```

Сначала предскажи текущий вывод и выпиши значения после каждой инструкции. Затем исправь порядок действий. Разрешены `let`, `=`, `-`, `console.log` и одна дополнительная переменная. Вход: целые `stock` и `sold` от 0 до 100, `sold <= stock`. Выход: старый и новый запас. Входные данные не относятся к объектам.

Проверки исправленного кода: `(10, 4) → 10 6`; `(0, 0) → 0 0`; `(5, 5) → 5 0`. Каждый вариант запускай независимо.

**По желанию:** для `balance`, `firstPurchase`, `secondPurchase` выведи остаток после первой и после второй покупки. Все значения — неотрицательные целые, сумма покупок не превышает баланс. Проверки: `(1000, 250, 150) → 750 600`; `(0, 0, 0) → 0 0`; `(500, 500, 0) → 0 0`. Функции пока не используй.

Типичная ловушка — сохранять «старое» значение уже после перезаписи.

**Вопрос собеседования:** почему порядок инструкций важен, если старое значение понадобится позже?
